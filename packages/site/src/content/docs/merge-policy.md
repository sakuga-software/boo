---
title: Merge policy
description: The rules that a team adds before ready to merge, so that an agent cannot merge too early.
---

"Ready to merge" means approved, green and mergeable for GitHub. A team can add its own rules in
`mergePolicy` in the settings file. A pull request that misses a rule shows `approved`, not
`ready to merge`, and its details give a note for each rule: `merge policy: no proof`. `m` refuses
to merge it and names the rules. `--json` gives the misses in `policy`.

```json
{
  "mergePolicy": {
    "minScore": { "reviewer": "sakuga-review", "score": 4, "onHead": true },
    "requireProof": "\\.(gif|webm|mp4)|No /tfp:",
    "resolvedBotThreads": true,
    "ownerOnly": { "paths": [".github/workflows/**", "**/migrations/**", "**/auth/**"], "owner": "mathieu" },
    "answeredReviewRequests": true,
    "answerFindings": ["P1", "P2"]
  }
}
```

| Rule                     | The pull request needs                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | Note                                                                                                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `minScore`               | A last confidence score of `reviewer` of at least `score`. With `onHead`, the score must come from a review of the head commit; a comment, such as the summary of Greptile, has no commit. With `deepest`, the deepest level of the reviews counts: ``{ "pattern": "Niveau `(\\w+)`", "levels": ["lite", "balanced", "heavy"] }`` gives the level of a review by the first group of `pattern`, and `levels` goes from the lightest to the deepest. The score is then the lowest score of that level, on the head commit with `onHead`, else on the commit of the last review of that level. A light review after a deep one does not replace it.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `no score from sakuga-review`, `no score from sakuga-review on head`, `score 3/5 on head, 4 needed`, `no heavy score from sakuga-review on head`, `heavy score 3/5 on head, 4 needed` |
| `requireProof`           | A match of this regular expression (case insensitive) in the description or in a comment: a link to a recording, or a reason with no test.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | `no proof`                                                                                                                                                                            |
| `resolvedBotThreads`     | No unresolved review thread that a bot starts (the first 100 threads). With `{ "goneMarker": "sakuga-review:gone" }` in place of `true`, a thread whose last comment is a bot comment with the marker counts as resolved: the bot says that its finding is gone. A reply of a person after it opens the thread again. A thread whose last comment is of the author of the pull request or of an agent of `authors` in the settings is answered: it waits only for a person who reads the answer and resolves it, and gets its own note.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | `2 open bot threads`, `1 answered bot thread to resolve`                                                                                                                              |
| `ownerOnly`              | If the pull request changes a file under one of `paths` (globs: `*` in a name, `**` for any folders), only `owner` merges it. The query reads the first 100 files: with more, only `owner` merges. `@me` is the account of `gh`, so a shared file names the owner by login.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | `mathieu merges`                                                                                                                                                                      |
| `answeredReviewRequests` | An answer of each bot that a comment asked for a review after its last review: a line that starts with the mention of the bot and contains the word `review`, such as `@sakuga-review review balanced`. A thank you to the bot is not a request. A review of that bot after the comment answers it. The comment of the bot itself does not count, but the comment of an agent that posts as a bot does.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | `review asked of sakuga-review, no answer yet`                                                                                                                                        |
| `answerFindings`         | An answer to each finding of a review bot with one of these levels, such as `["P1", "P2"]`. A finding is a line with a level badge (`<img alt="P2" …>`) and a bold title, in an open review thread of a bot, in the last review of a bot, or in the block of Sakuga Review in the description. An answer comes from the author of the pull request or from an agent of `authors` in the settings (`app/my-agent`): never from a review bot, a CI bot, or another person who discusses the finding. A thread has an answer if its last comment is such an answer; a later comment of the bot opens it again. The rule checks that an answer exists, not what it says: a person reads it before the merge. A finding of a review or of the description has an answer if such a comment quotes its title or gives its short ID (`#1631f7`); a title shorter than 20 characters needs the ID; for a review, only a comment after the review counts. The block of the description has no time, so a comment of any time counts: a finding that comes back in a later round, with the same title or ID, keeps its answer. The threads are read only with this rule or `resolvedBotThreads`; a read with no threads misses the rule. | `2 P2 not answered (description)`, `1 P1 not answered (thread)`                                                                                                                       |

## A review App with several logins

A review App that changes its name posts under a new login, and the old pull requests keep the
reviews of the old login. `reviewer` can then be a list of logins that count as one reviewer. The
first login names it in the notes. `commands` lists the other mentions that ask it for a review:

```json
{
  "minScore": {
    "reviewer": ["kento-review", "sakuga-review"],
    "commands": ["@kento-ai", "@kento"],
    "score": 4,
    "onHead": true,
    "deepest": { "pattern": "Niveau `(\\w+)`", "levels": ["lite", "balanced", "heavy"] }
  }
}
```

- `minScore` reads the score of the last review of any of these logins.
- `answeredReviewRequests` takes a request to one of them, such as `@sakuga-review review` or
  `@kento-ai review`, and a review of any of them answers it. With `deepest`, a level right after the
  mention also asks for a review: `@kento-review heavy`. Another command, such as
  `@kento-review reject`, does not.
- `resolvedBotThreads` already counts the threads of every bot login.

Some bots write in a thread that its finding is gone, but an agent may have no right to resolve the
thread. Sakuga Review writes the marker `<!-- sakuga-review:gone -->` in that comment.

A rule with a missing or invalid field is dropped. `resolvedBotThreads` and `ownerOnly` make each
query read the threads or the files, and cost about one GraphQL point more for each pull request.
